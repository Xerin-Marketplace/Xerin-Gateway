Xerin Logistics Onboarding - Phase 1
=====================================

This phase creates the company, login user, global company_admin role and
primary logistics membership in one database transaction. It then sends the
welcome email. New companies always start as pending.

Backend files:
- api/config.py
- api/schemas.py
- api/routers/logistics.py
- api/routers/auth.py
- tests/test_logistics_company_onboarding.py

Frontend files:
- src/lib/api/endpoints/admin.ts
- src/components/Admin/Configuration/index.tsx

Backend .env:

LOGISTICS_PORTAL_LOGIN_URL=https://xerinmarketplace.com/signin

Existing EMAIL_* SMTP values must be configured for welcome-email delivery.
The database account is not rolled back when SMTP is temporarily unavailable;
the API response returns welcome_email_sent=false and a warning.

Validation:

Backend:
source .venv/bin/activate
python -m compileall api
pytest tests/test_logistics_company_onboarding.py -q
alembic upgrade head

Frontend (from the full frontend project root after copying src files):
npx tsc --noEmit --pretty false
npm run build

No new database migration is required in Phase 1.

Admin flow:
Admin Dashboard -> Logistics -> Logistics Companies
Enter company name/code and the first administrator's name, email, optional
phone and temporary password. The frontend calls:

POST /api/v1/logistics/companies/onboard

The administrator signs in with the email and temporary password, and is
routed as account_type=logistics. The welcome email never contains the
temporary password.

Phase 2 will add the first-login welcome page and guided checklist for company
profile, zones, services, charges and payout account. Webhook setup is optional.
